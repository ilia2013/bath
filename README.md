# Brawl AI — самообучающийся ИИ-агент для Brawl Stars

Фреймворк для обучения ИИ-агента играть в аркадный 2D-бой в стиле Brawl Stars
через self-play (обучение с подкреплением против собственных прошлых версий).

## ⚠️ Важно: честная игра и ToS

Brawl Stars — живая онлайн-игра с реальными людьми. Автоматизация ввода
против настоящих игроков в рейтинговых/ранговых режимах — это читерство,
нарушает Terms of Service Supercell и может привести к бану аккаунта, а
также портит игру другим людям.

**Этот проект спроектирован для тренировки офлайн / против ботов игры
(Practice-режим), а не против живых игроков.** Модуль `brawl_ai/real/*`
даёт технические примитивы (захват экрана, ADB-управление), но не
автоматизирует матчмейкинг против людей, и я не буду добавлять это.

## Что реально работает прямо сейчас

`brawl_ai/env/` — полностью самодостаточная симуляция 2D-арены (движение,
прицеливание/стрельба, боезапас, стены-укрытия, супер-способность, здоровье),
реализованная как `gymnasium.Env`. Она не требует ни игры, ни телефона, ни
эмулятора — это позволяет по-настоящему обучать и тестировать RL-пайплайн
здесь и сейчас.

```bash
pip install -r requirements.txt

# быстрая проверка среды
python3 -c "
from brawl_ai.env import MockBrawlArenaEnv, ScriptedBot
env = MockBrawlArenaEnv(opponent=ScriptedBot())
obs, info = env.reset()
print(obs.shape)  # (64, 64, 3)
"

# обучение self-play PPO (агент играет сам против себя + встроенного бота)
python3 -m brawl_ai.train --timesteps 500000 --n-envs 8

# оценка результата против скриптованного бота
python3 -m brawl_ai.evaluate --model brawl_ai/checkpoints/ppo_brawl_final.zip --episodes 50
```

Я прогнал короткий smoke-тест (60k шагов, ~2 минуты на CPU): пайплайн
env → self-play опонент-пул → PPO → чекпоинты → оценка отработал целиком
без ошибок, метрики обучения (loss, KL, энтропия) вели себя ожидаемо.
**60k шагов недостаточно для сильной игры** — это лишь доказательство
работоспособности механизма. Чтобы агент реально заиграл прилично,
нужны десятки-сотни миллионов шагов (часы-дни обучения, как в любом RL
для игр — OpenAI Five, AlphaStar и т.п. учились неделями на кластерах).

## Архитектура

```
brawl_ai/
  env/
    mock_arena.py    — симулированная арена (Gym env), CNN-совместимый RGB observation
    opponents.py      — ScriptedBot (эвристика для разгона), FrozenPolicyOpponent
                        (заморженный чекпоинт для self-play), OpponentPool,
                        CurriculumOpponentEnv (постепенный переход scripted → self-play)
  train.py            — self-play PPO обучение (stable-baselines3)
  evaluate.py          — оценка модели (win rate, средняя награда)
  real/                — хуки для реального устройства (см. ниже)
    capture.py          — захват экрана окна эмулятора/зеркала телефона (mss)
    controller.py        — управление через adb (виртуальные джойстики)
    detector.py           — CV-оценка HP по полоскам здоровья (цветовые маски)
    real_env.py            — единый Gym env поверх этих трёх модулей
```

### Как устроено self-play

1. Агент играет против встроенного эвристического бота (`ScriptedBot`), пока
   нет ни одного сохранённого чекпоинта — это "разгон", иначе учиться не от
   чего.
2. `train.py` периодически сохраняет чекпоинт модели в `checkpoint_dir`.
3. `OpponentPool` на каждый эпизод (или раз в N эпизодов) выбирает
   противника: с некоторой вероятностью — `ScriptedBot`, иначе — случайный
   чекпоинт из пула, загруженный как замороженный (не обучаемый) оппонент.
4. Со временем доля self-play растёт естественным образом — чем больше
   чекпоинтов накоплено, тем реже выбирается скриптованный бот.
5. Один и тот же наблюдаемый формат (`render_for("hero" / "opponent")`)
   рисует картинку с точки зрения любой из сторон, поэтому одна и та же
   сеть управляет и "собой", и заморженной копией себя же.

## Реальное устройство (эмулятор/телефон) — требует калибровки

`brawl_ai/real/` даёт рабочие строительные блоки, но НЕ готовое
"из коробки" решение — координаты джойстиков, зона захвата экрана и
цветовые пороги для полосок здоровья намертво зависят от вашего
разрешения экрана, версии игры и layout окна. Это невозможно
захардкодить универсально без доступа к реальному устройству.

Что нужно сделать самостоятельно для реального деплоя:

1. Установить Android platform-tools (`adb`), подключить эмулятор
   (BlueStacks/Waydroid/LDPlayer) или телефон (`adb devices` должен видеть
   устройство).
2. Замерить пиксельные координаты левого (движение) и правого
   (прицел/выстрел) джойстиков на экране — заполнить
   `real.ControllerConfig`.
3. Сделать несколько скриншотов боя и подобрать ROI + HSV-диапазон для
   полосок здоровья своего и чужого юнита — заполнить `real.DetectorConfig`.
4. Прописать навигацию по меню (кнопка "Играть снова"/выбор Practice-режима)
   — это специфично для UI и намеренно не захардкожено.
5. **Использовать только Practice-режим / бои против ботов игры.**

```python
from brawl_ai.real import (
    RealBrawlStarsEnv, RealEnvConfig, CaptureRegion,
    ControllerConfig, JoystickCalibration, DetectorConfig, HealthBarROI,
)

config = RealEnvConfig(
    capture_region=CaptureRegion(left=0, top=0, width=900, height=1600),
    controller=ControllerConfig(
        move_joystick=JoystickCalibration(center_x=180, center_y=1300, radius_px=120),
        aim_joystick=JoystickCalibration(center_x=720, center_y=1300, radius_px=120),
    ),
    detector=DetectorConfig(
        own_hp_bar=HealthBarROI(x0=100, y0=1200, x1=260, y1=1215),
        enemy_hp_bar=HealthBarROI(x0=600, y0=200, x1=760, y1=215),
    ),
)
env = RealBrawlStarsEnv(config)
```

Модель, обученную в симуляции, можно загрузить сюда (`PPO.load(...)`), но
ожидайте sim-to-real разрыв — картинка симуляции и реальный экран выглядят
по-разному, так что потребуется дообучение (fine-tuning) на реальных кадрах.

## Ограничения

- Симулированная арена — упрощение реальной игры (нет разных бойцов с
  уникальными способностями, нет команд 3v3, нет сбора гемов/режимов).
  Легко расширяется добавлением новых типов юнитов/режимов в `mock_arena.py`.
- Реальный CV-детектор здоровья — эвристика по цвету полоски, а не точное
  чтение состояния игры; чувствителен к освещению/теме UI и потребует
  подстройки под конкретную версию игры.
- Обучение требует значительного времени работы (часы на GPU для приличного
  уровня игры), это не одноразовый мгновенный запуск.
